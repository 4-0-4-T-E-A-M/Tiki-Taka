# 티켓팅 프로젝트 주차별 역할 분담

## 팀 구성

- **노주희** — 예매(Booking) 도메인 + Redis 분산 락 + Kafka Producer
- **신선우** — 공연/좌석(Concert/Seat) 도메인 + 대기열 + SSE + 공연 오픈 스케줄러 + Elasticsearch + QueryDSL + 캐시 히트율 튜닝
- **조준형** — 유저/알림(User/Notification) 도메인 + Spring Security·JWT + Kafka Consumer + Prometheus·Grafana + k6 총괄
## 전체 예매 흐름

```
공연 오픈 스케줄러 (신선우)
    └── 좌석 AVAILABLE 전환 + 대기열 입장 허용
 
대기열 (신선우)
    ├── Redis Sorted Set 순번 관리
    └── SSE 순번 실시간 푸시
            └── 대기열 통과 시 예매 페이지 입장
 
예매 (노주희)
    ├── 분산 락 획득
    ├── 좌석 상태 확인 + RESERVED 변경
    ├── 예매 레코드 생성
    └── Kafka 이벤트 발행
            ├── Consumer (조준형): 이메일 알림
            └── Consumer (조준형): 예매 통계 집계 → Grafana 시각화
```

Kafka 도입 이유: 예매 완료 이후 알림·통계 처리를 decoupling하여 멀티 컨슈머 확장성 확보
